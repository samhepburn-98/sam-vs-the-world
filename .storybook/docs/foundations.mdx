# Sam vs the World — design system

This Storybook is the living reference for the app's **Broadcast** design
system: sports-TV information graphics built around the FUT-style player
cards. Every component you would *place on a page* has a story here. Two
kinds don't: page-level compositions that assemble a whole screen region
(the profile tabs, the head-to-head panel, category content) — those are
documented in [Page anatomy](?path=/docs/patterns-page-anatomy--docs) — and
`SiteHeader`, which imports a server function whose module chain Storybook's
build deliberately excludes.

Everything renders from the **live CSS variables** in `src/styles.css`, so
these docs cannot drift from the app.

**Planning a page?** Start at [Pick a component](?path=/docs/foundations-pick-a-component--docs)
— it's organised by what you're trying to say rather than by what things are
called. [Page anatomy](?path=/docs/patterns-page-anatomy--docs) then shows how
the existing pages are assembled from those pieces.

## The one-paragraph version

Broadcast is **studio graphics with two lighting rigs** — flat surfaces in
three depth steps (graphite-navy night rig by default, a paper-grey
daylight rig for bright rooms), square corners everywhere, Barlow Condensed
shouting the headlines from skewed lozenge badges. The two team colours are the only
accents, and **every value that belongs to a player wears their side**:
ember for player one, blue for player two. Results speak through the status
tokens as W/L/D chips. The player card is the one crafted, textured object;
everything around it is a flat graphic with a slot for a number.

The details live in the neighbouring pages:

- **Colors** — the palette, the colour law, status tokens, and the chart
  ramp. No gradients exist.
- **Typography** — the two Barlow voices and the heading primitives.
- **The Broadcast rules** — what keeps this a design system instead of a
  costume.

## The graphic shapes

The system is a kit of broadcast graphics, each a story in the sidebar:
**Ticker** (full-bleed strip), **Callout** (accent-bar pundit panel),
**ScoreStrip** (deep full-time graphic), **ResultChip / FormGuide** (W/L/D
in status colours), **StatRow** (the label-and-number lower-third),
**RecordTile** (the records wall — each tile wears the holder's side from
the match the record was set in), and the skewed **brand lozenge**
(`skew-badge` utilities).

## Where things go

- `src/components/ui` — shadcn primitives, themed by tokens only.
- `src/components/broadcast` — the graphic kit above.
- `src/components/{layouts,court,rally}` — page furniture, court SVGs, and the
  rally-entry composites. `typography.tsx` sits at the root: it's the type
  scale, not a graphic.
- `src/features/*` — feature-specific components; a feature never imports a
  sibling feature.
- Stories live next to their component as `*.stories.tsx`.

The sidebar and the folders answer different questions, so they don't match
one-for-one: a folder says **who owns this**, a sidebar section says **what
kind of thing it is**. `RecordTile` lives in the dashboard feature (it reads a
dashboard type) but files under **Broadcast** here, because that's where
you'd look for it when planning a page.

## Working rules

- **Semantic over raw.** Components reference tokens (`text-success`,
  `bg-p2`, `text-primary-strong`), never one-off colours.
- **Headings are componentised.** `PageTitle`, `SectionTitle`, and
  `Overline` are the only way titles render.
- **Charts are recharts** wherever a chart type exists for the data; court
  visuals stay hand-drawn SVG.
- **Phone-first.** Every surface works at 390px with 44px hit targets before
  it earns a desktop layout.
