# Pick a component

Start here when you're planning a page. Find the row that matches what you're trying to
**say**, not what you want it to look like — the design system already decided the looks.

Everything below is in the sidebar; the section is where to find it.

## Say a number

| You want to show | Reach for | Section |
| --- | --- | --- |
| A rate you must not fake | **Stat card** — a `{ won, of }` pair, so a percentage *cannot* render without its denominator | Dashboard |
| One number in a grid of numbers | **Stat tile** | Broadcast |
| A label-and-value line, stacked into a block | **Stat row** | Broadcast |
| A proportion as a bar, in a list of them | **Stat bar row** | Dashboard |
| A number that should count up on arrival | **Count up** | Broadcast |
| An all-time best | **Record tile** / the wall | Broadcast |

There are four "stat" components because there are four shapes, not four opinions: a **card**
is a rate with its receipt, a **tile** goes in a grid, a **row** is a lower-third line, a
**bar row** is a proportion. If you're unsure, you probably want Stat card — it's the one that
enforces the honesty rules.

## Building the logger

The live rally logger has its own kit, tuned for speed at 2× playback. If you're adding to that
screen, start here rather than in Broadcast.

**Score header** (the giant running score, serving dot, box and serve chips) ·
**Winner buttons** (two big targets plus let) · **Outcome chips** (end reason, then the conditional
detail/forced/shot-type/count) · **Undo bar** · **Sync indicator** (the write queue's three states) ·
**Game over banner** · **Rally timeline** · **Match setup** · **Player select** ·
**Recent matches** · **Hotkey help** (`?`) · **Glossary**.

## One orphan, on purpose

**Insight card** has no caller, and it is the *only* thing in the app that links to a category
page (`/players/$playerId/$category`). So the whole category chain — that route, `CategoryContent`
(377 lines), `FilterBar`, `CATEGORY_KEYS` — is currently reachable only by typing a URL.

It is left in the catalogue rather than deleted precisely because deleting the bridge would
quietly cement an orphaned feature. The decision to make is *wire it back up or remove the chain* —
not "tidy away the one component that still points at it".

## Primitives

Buttons, inputs, tabs, dialogs, tables — the shadcn layer, themed by tokens only. They're in the
sidebar under **Primitives** for reference, but they're not in the tables above: you already know
what a Button is, and the interesting decision is which *domain* component wraps it.

Never edit a primitive for one screen. If a screen needs something a primitive doesn't do, that's a
new component in `broadcast/` or the feature, built on top.

## Before you compose

Four rules the kit assumes. Breaking them is what makes a new page look like a different app.

1. **The colour law.** Every value belonging to a player wears their side — ember for player one,
   blue for player two. The prop is always called `side`. `tone` means emphasis that is nobody's
   colour; `outcome` is the only one that carries a verdict. See **The Broadcast rules**.
2. **Show the denominator.** A percentage without its sample is a lie the components are built to
   make difficult. Prefer the component that enforces it over one that lets you print a bare number.
3. **Phone first.** Every surface works at 390px with 44px hit targets before it earns a desktop
   layout. Check a story at mobile width before you believe it.
4. **Say the gap out loud.** When there isn't enough data, the kit shows a dash or "Not enough data
   yet" — it never invents a number and never silently disappears.

## Where things live

The sidebar and the folders answer different questions on purpose — a folder says *who owns
this*, a sidebar section says *what kind of thing it is*. `Record tile` files under **Broadcast**
because that's where you'd look for it, but lives in the dashboard feature because it reads a
dashboard type. `docs/architecture.md` has the folder rules.
